#### Design Specificity Verdict

**Partially grounded.** The wireframe corner handles on folder tiles and `.fmini` dot-matrix progress indicators are genuinely composite-art-literate — they echo viewport selection handles and material-slot indicators. The color-per-tool mapping (Blender=orange, Substance=purple, Unity=blue) is domain-specific. The `_bases` library with cover art and "IMPORT IN BLENDER" action is compositor workflow. The pipeline bar with contextual tooltips ("Uses Blender · Completed") turns a decorative element into an informational one.

However, 70%+ of the visual system — dark mode, rounded cards, gradient borders, accent glow, pill badges, breadcrumbs, empty states — is stock dark-theme productivity UI. The dot-grid background could belong to any dev tool. Syne + Space Mono font pairing is overused in indie SaaS. The app doesn't yet *feel* like it was designed *from* the 3D artist workflow outward; it feels like a competent dark-theme CRUD app that *serves* one.

#### Cognitive Load Assessment

**Checklist: 2/8 passed**

- **FAIL** — Chunking: info panel shows 4 stat cards + 8 storage rows + progress bars simultaneously
- **FAIL** — Progressive disclosure: all pipeline stages visible at all times, export section always present for FBX folder
- **FAIL** — Consistency: multiple button, modal, and form systems force relearning across screens
- **FAIL** — Minimal decision points: new project requires name + 8 folder checkboxes + root path = 3+ simultaneous decisions; new export has 6 fields
- **PASS** — Spatial stability: sidebar/main/panel grid doesn't shift
- **PASS** — Feedback latency: most interactions are synchronous DOM updates
- **FAIL** — Semantic grouping: FBX folder mixes file list + export management + unassigned files in one scrollable view
- **FAIL** — Recognition over recall: export naming variables `{target}`, `{version}` shown as chips but no inline explanation

**Working memory violations:**
- Pipeline bar: users must remember which stage they clicked and what "active" means
- Export modal: users must remember target name across modal open/close
- Folder tiles: 8 tiles visible simultaneously, each requiring hover to see count/size

#### Emotional Journey

**What works:** Project card with thumbnail creates genuine emotional attachment; pipeline green checkmark glow provides satisfying micro-reward; "ALL DONE" message is clear end-of-task payoff.

**What's missing:** First-use anxiety with no onboarding; "cannot be undone" message for local file operations that are technically undoable; no celebration at pipeline completion; settings overwhelm with 5 sections.

#### What's Working

1. **Wireframe corner handles on folder tiles** — the single most product-specific design element. L-shaped border trick on hover directly references 3D viewport selection brackets. Subtle, discoverable-only-on-hover, and domain-meaningful.

2. **Soft-delete with undo toast** — 5-second undo window with prominent UNDO button in accent color replaces anxiety with confidence. Toast positioning and stacking work well.

3. **Pipeline bar with contextual tooltips** — each stage shows "Uses Blender · Completed" / "Current stage" on hover. Turns a decorative element into informational without cluttering default view.

#### Priority Issues

### P0 — Consistency Debt
**What**: Three button systems, five modal patterns, two form label conventions coexist. Legacy `.btn-pri`/`.btn-sec` aliases duplicate full rule blocks. `.wf-overlay`/`.wf-form` creates yet another modal system in settings.
**Why**: Every new feature requires choosing which system to use; users encounter inconsistent button sizing, spacing, and hover behavior across screens.
**Fix**: Consolidate to `.btn-primary`/`.btn-secondary`/`.btn-ghost`/`.btn-danger`. Migrate `.wf-overlay`/`.wf-form` to `.ov-modal`/`.modal-box`. Remove legacy aliases.
**Suggested command**: `$impeccable polish`

### P1 — Cognitive Overload in Project View
**What**: When a project is active, the main area shows pipeline bar (5-8 stages), project header, tab bar, folder tiles (8 items), AND info panel (4 stats + 8 storage rows + progress bars). 20+ distinct data points before any action.
**Why**: Users can't focus on a single task because everything demands attention simultaneously.
**Fix**: Collapse info panel into toggleable drawer. Progressive-disclose storage rows. Reduce to 2-3 summary stats by default.
**Suggested command**: `$impeccable distill`

### P1 — No Keyboard Navigation in Core Workflows
**What**: File list, sidebar project list, and pipeline bar are all click-only. No arrow-key navigation, no Enter to activate, no Tab order management.
**Why**: Artists who use Blender (keyboard-heavy) will find this friction point daily. Power users can't work efficiently.
**Fix**: Add `tabindex`, `role="listbox"`/`role="option"`, and `keydown` handlers to project list and file list.
**Suggested command**: `$impeccable harden`

### P2 — Pipeline Stage Click Ambiguity
**What**: Clicking any `.pnode` sets `p.stage = i + 1`. Clicking stage 1 when on stage 3 regresses two steps with no confirmation. Tooltip says "Not yet reached" for future stages (implying not clickable).
**Why**: Accidental stage regression is trivial and loses progress tracking.
**Fix**: Either lock clicks to only advance (with confirmation for >1 step), or visually differentiate "click to go back" from "click to advance".
**Suggested command**: `$impeccable clarify`

### P2 — Raw Error Messages
**What**: Error strings like `'Error: ' + e` and `'Failed to launch: ' + err` expose raw Tauri/JS exceptions to users.
**Why**: Technical error text is confusing and demoralizing for non-developer users.
**Fix**: Map common Tauri errors to user-friendly messages with recovery suggestions.
**Suggested command**: `$impeccable clarify`

#### Minor Observations

- Font loading: Syne and Space Mono referenced but no `@import` in CSS. If CDN fails, UI degrades silently
- Thumbnail base64 stored in `project.json` will balloon file size for projects with many images
- Export cover loading scans `_bases/` directories on every `renderFileList` — potential perf issue with many targets
- `!important` on rename input in bases.css suggests specificity conflicts
- 4px scrollbars may fail WCAG target size requirements

#### Questions to Consider

1. When a user completes the final pipeline stage, should there be a distinct celebration moment rather than a green toast?
2. Is the calendar view (year/month/week) actually used by composite artists, or does it add unnecessary complexity?
3. Should the Blender addon drag-install have a fallback "click to copy file path" option for users who don't discover the gesture?
4. With 2 themes, is the theme system worth the CSS maintenance, or would users prefer one polished theme?
5. The `_bases` library is powerful but completely undiscoverable — should there be a getting-started walkthrough?

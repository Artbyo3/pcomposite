3. **Thoughtful state feedback.** The delete-undo toast with 5s window, confirm modal for pipeline skip, and contextual tooltips on folder tiles and pipeline stages show attention to interaction detail.

## Priority Issues

### P1: Contrast failures across the entire secondary text layer
- **What:** `--text3` (#484858) scores 1.9:1 against `--bg` (#0c0c0e). `--text4` (#303040) scores 1.3:1. `--text2` (#7a7a90) scores 4.2:1 — borderline fail. All three are used extensively for labels, metadata, and secondary text.
- **Why it matters:** Violates WCAG AA (4.5:1 minimum). Affects all users in bright environments, and completely blocks Sam (accessibility-dependent) from reading secondary information.
- **Fix:** Bump `--text3` to at least #6a6a80 (5.5:1), `--text4` to #505060 (3.5:1 minimum for large text), and `--text2` to #8a8aa0 (5.0:1). These maintain the dark aesthetic while becoming readable.
- **Suggested command:** `$impeccable colorize`

### P2: No `:focus-visible` styles anywhere in the codebase
- **What:** Zero focus indicators across all interactive elements — buttons, links, project cards, file rows, pipeline stages, tabs. The keyboard navigation we added (tabindex, role, keydown handlers) is invisible without focus styles.
- **Why it matters:** Sam cannot see where keyboard focus is. Alex (power user) navigating by keyboard loses context immediately. This makes the keyboard navigation we added functionally broken.
- **Fix:** Add a global `:focus-visible` rule: `outline: 2px solid var(--accent); outline-offset: 2px; border-radius: 4px;` on all interactive elements. Ensure the outline is visible against the dark background.
- **Suggested command:** `$impeccable harden`

### P2: Inline styles pervasive in index.html
- **What:** 14+ inline style clusters in `index.html`, including the thumbnail element (230+ chars), progress bars, image viewer lightbox, and action buttons. `checklist.js:29-33` has 15+ inline style properties on a single div.
- **Why it matters:** Undermines the design system — styles can't be overridden, themed, or maintained consistently. The pink theme can't affect inline-colored elements. Future refactor becomes exponentially harder.
- **Fix:** Extract inline styles into CSS classes: `.ph-thumb`, `.progfill`, `.iv-*` (image viewer), `.abtn-icon`, `.pbody-empty`. Use CSS custom properties for dynamic values (width, background-color set by JS).
- **Suggested command:** `$impeccable polish`

### P3: Dead "Delete Project" button
- **What:** "Delete Project" in Actions panel shows `showToast('Delete not yet implemented','var(--red)')`.
- **Why it matters:** Alex will click it expecting functionality. Jordan will be confused by the error. Broken promises erode trust.
- **Fix:** Either implement delete with confirmation, or remove the button entirely until ready. A dead button is worse than no button.
- **Suggested command:** `$impeccable harden`

### P3: `.mbody2` CSS conflict between modal.css and settings.css
- **What:** `modal.css:39` defines `.mbody2 { padding: 18px 22px }`. `settings.css:264` redefines `.mbody2 { padding: 16px 22px; flex:1; display:flex; flex-direction:column; gap:12px }`. Winner depends on load order.
- **Why it matters:** Fragile cascade — changing CSS import order in `main.js` could break modal layouts. The settings-specific overrides should be scoped.
- **Fix:** Scope settings overrides: `.mbody2.settings-body { ... }` or remove the duplicate from `modal.css` if settings.css is the authoritative definition.
- **Suggested command:** `$impeccable polish`

## Persona Red Flags

### Alex (Power User)
- **No bulk operations.** Cannot select multiple files to move, delete, or export. Each file requires individual right-click.
- **Keyboard nav incomplete.** Pipeline and project list support arrows, but no Home/End, no Ctrl+A for select-all, no Ctrl+F for file search (only the filter input in FBX view).
- **Settings require many clicks.** Adding a tool: click "+ ADD TOOL" → fill 4 fields → Save → re-render. No inline editing.

### Jordan (First-Timer)
- **Terminology barrier.** "Vault Path", "Pipeline Stages", "FBX Versioning", "Base ID" — all appear without explanation in Settings.
- **No visible first action.** After selecting a project, folder tiles appear but no indication of what to do first.
- **Context menus required for discovery.** File actions only accessible via right-click. The "Open in..." button only appears on hover.

### Sam (Accessibility-Dependent)
- **Contrast failures.** --text3 and --text4 are nearly invisible against the background. Secondary information is unreadable.
- **No focus indicators.** Keyboard navigation exists but is invisible without :focus-visible styles.
- **Missing ARIA labels.** Toolbar SVG buttons, project header action buttons, and pipeline arrow icons have no aria-label.

## Minor Observations

1. **Dot-grid background is nearly invisible.** `opacity: .12` at `style.css:51` makes it almost imperceptible on most monitors. Bump to `.18` for deliberate texture.

2. **Two theme options is thin.** Dark and Pink themes only swap color values — no layout or component variations. Consider a custom accent color picker.

3. **Thumbnail base64 bloat.** `thumbnail.js:32` stores images as base64 data URLs in project.json. For projects with many images, this will bloat files significantly.

4. **Pipeline labels use emoji.** The pipeline stage icons (🎨 📦 🚀 etc.) are emoji — inconsistent with the app's otherwise icon-system approach (SVG for tool icons). Consider SVG stage icons.

5. **Export modal complexity.** The versioning system requires manual export records, file assignment, and "current" marking. For a v0.0.7 app, this may be premature complexity.

## Questions to Consider

1. **Does the right panel earn its 285px?** Info tab shows 4 sections that could be collapsible. Actions tab duplicates buttons from the project header. Could the panel be toggled/collapsible?

2. **What if the checklist drove the entire experience?** Instead of three equal tabs, what if each pipeline stage expanded to show relevant folders and files? This would align the UI with how artists actually think about their pipeline.

3. **Is the export system solving a real problem?** The versioning system requires manual record-keeping. Could exports be auto-tracked from file metadata or Blender addon activity?
